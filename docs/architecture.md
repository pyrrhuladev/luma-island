# Архитектура Luma Island

Приложение — native Windows HUD на C#/WPF. `App` соединяет существующие источники данных с `MainWindow` и управляет их жизненным циклом. Музыка и громкость используют события Windows; часы и батарея обновляются раз в минуту. Нагрузка и температуры опрашиваются раз в две секунды, когда они нужны компонентам или предупреждениям.

| Часть | Назначение |
|---|---|
| `MainWindow` и его partial-файлы | HUD, оформление, ограниченные истории графиков, музыка, положение, пропуск кликов и маркер |
| `PerformanceService` | Общий фоновый сбор нагрузки и температур; для CPU/RAM читает необязательный локальный модуль |
| `FpsService`, `FrameViewSource`, `FrameTimingState` | Одна сессия установленного SDK, проверка PID/потока и свежести, ограниченная передача реальных кадров в UI |
| `MonitorRequirements` | Объединение запросов видимых компонентов и включённых предупреждений; при скрытии HUD запросы выключаются |
| `HudAlertEngine` | Состояние предупреждений по существующим измерениям и монотонному времени, без отдельного сборщика |
| `HudEditorWindow` и `HudPreviewSession` | Единое окно настроек, поиск, локальный черновик и никогда не показываемое дерево настоящего HUD с демонстрационными данными |
| `SettingsSectionRegistry`, `SettingsSectionDefinition` | Стабильные ID разделов, поиск по метаданным, фабрики страниц и обработчики захвата/проверки/закрытия |
| `SettingsEditorContext`, `SettingsApplicationPages` | Снимок исходного контекста и локальные страницы положения, игровых привязок и приложения |
| `SettingsCommitPlan` | Чистый выбор итогового HUD и цели сохранения перед изменением stores |
| `QuickMenuTheme` | Общие стили коротких контекстных меню HUD и трея |
| `GameProfileController` и stores | Маршрутизация изменений в активный игровой профиль или общие локальные настройки |

`AppearanceSettings` содержит value-only настройки раскладки и предупреждений. Строки порядка приводятся к известным уникальным ключам; размеры и пороги ограничиваются при загрузке и сохранении. Значения по умолчанию сохраняют прежний HUD и выключают предупреждения. Пропуск кликов остаётся общей настройкой и не переключается профилем игры.

Редактор не запускает `App`, FrameView или сборщики в предпросмотре. Изменения живут в черновике до подтверждения; после закрытия освобождается дерево предпросмотра. Пока открыто окно, выбор игрового профиля приостановлен. Изменение раскладки не добавляет периодического таймера отрисовки. Маркер использует один таймер только для истечения уже активного состояния.

Разделы регистрируются через `HudEditorWindow.RegisterSection`. `SettingsSectionRegistry` хранит порядок и индекс стабильных ID; поиск учитывает название, описание и ключевые слова. `SettingsSectionDefinition.GetContent` вызывает фабрику только при первом выборе, а `ReleaseContent` освобождает ресурсы созданной страницы при закрытии. Оболочка помещает содержимое в общий `ScrollViewer`; существующий корневой `ScrollViewer` страницы используется повторно. Обработчики `CaptureDraft` и `Validate` участвуют в общем подтверждении. Внешние DLL или скрипты для регистрации не загружаются; стили настроек не меняют ресурсы HUD.

`SettingsCommitPlan.Create` нормализует и клонирует входные снимки без записи файлов. При сохранении активной игры её итоговый HUD объединяется с черновиком профилей до передачи в контроллер. С выключенной автоматикой текущий вид сохраняется также как общий. Если исходный активный профиль удалён, план возвращает исходный общий HUD, без переноса удалённого игрового черновика в обычные stores. Без исходного активного профиля HUD сохраняется как общий. Остальные привязки и их правки сохраняются во всех случаях. Пропуск кликов остаётся глобальным и исключается из игровых снимков.

`ApplySettingsDraft` заменяет конфигурацию профилей, выбирает рассчитанную цель и применяет вид под `SuppressWrites`; `CaptureCurrent` вызывается для активной игры или явно выбранного сохранения как общего. На удалении активного профиля захват общего HUD пропускается. Ошибки независимых stores учитываются в результате сохранения; полной файловой транзакции между ними и регистрацией автозапуска нет. Автозапуск записывается только при изменении его черновика и не отменяет `StartupApproved`. Установка датчиков остаётся отдельным явным действием.
